# 指揮した録音を、同じボタンで聴く・止める

## 見つかった不具合

実際に「新世界より」の前半を指揮して自然終了し、結果画面から聴き返すと、再生中も「もう一度聴く」のままだった。`aria-pressed`もなく、Escapeで閉じた後も同じ再生が続いていた。`before-result.json`・`before-replay.json`・`before-close.json`に記録。

## 変更

- `listenConductResult`で、同じ録音の再生・待機中なら停止し、止まっているときは従来の`playRecording`へ渡す。
- `renderConductResultPlayback`を再生状態の更新に加え、実際の録音idで照合。「止める」・「読み込みをやめる」・元の「もう一度聴く」とSVG・金色の面・`aria-pressed`をそろえる。ボタン自体は作り直さない。
- 自然終了で表示を戻す。`closeConduct`は結果画面からの聴き返しと待機も止めるので、上の閉じる・Escapeでも音を止めて戻る。
- 結果の4操作を高さ46px以上の等幅2列へそろえ、再指揮にも既存の指揮棒SVGを使う。結果を見るだけの1ボタンは横いっぱい。演奏が終わったら上の「やめる」も「閉じる」へそろえる。

判定・指揮の効き・音・成長・録音内容・セーブ形式は変更していない。保存は従来の処理へ同じ`CD.rec`を渡す。新しい素材・フォント・動く演出は追加していない。

## 確認

- 375×812のライト・ダークで、実際に4回数えて指揮を開始、自然終了して録音を作成。その録音を結果画面から聴き返し、同じボタンで停止。ボタンは操作先を保ち、再生中と待機中の印を更新する。
- 再生した演奏のハッシュと、保存済みの録音から作る演奏が一致。再生の時計も保存済みの指揮の`ev`と一致。再生途中に`SampleVoice`で鳴ることを確認。最初の休符中は発音中の音源が0でも、再生の時計は進む。
- 保存ボタンが同じ録音id・スナップショットを渡すことを照合。確認ページの`exportAudit`で実保存は行わず、呼び出し先を記録した。
- 同じボタンで読み込み待ちを中止し、解放後も鳴らない。自然終了後も結果に残り、「もう一度聴く」へ戻る。聴き返し・停止・待機の中止・保存の呼び出しで部と録音が不変。
- 待機中から「もう一度指揮する」を押すと、古い待機を中止。音源を解放してもまだ鳴らず、数え始めからやり直せる。新しい指揮を自然終了したときだけ録音が1件増える。
- 375×667でもライト・ダークの4操作が46px以上で画面内に収まる。読み込み待ちのラベルも折り返さず、等幅の2列を保つ。
- 聴き返し中にEscapeで閉じると再生を停止。上の閉じるでは読み込み待ちも中止し、解放後も鳴らない。どちらも元の合奏の指揮ボタンへ操作先が戻る。録音は増えず、部の状態も変わらない。
- 49操作で2027年度へ進行。33スクリプトの起動失敗、コンソール警告・エラーなし。
- `browser-check.json`は各操作直後に保存。`browser-assertions.txt`で状態・音・時計・寸法を照合。
- `node tsukurikata/tools/check_conduct_result.js`：再生・停止・自然終了・読み込み中止・結果の終了処理からの停止・別の録音との区別・部と録音の不変を確認。
- オーディションの試聴、個人録音の停止、指揮の予告と入力時刻の既存検証も合格。各`*-check.txt`を保存。
- 字の検査は既存の5記号（▶♩♮⤓𝄪）とコードコメントの「常」が不足。操作ボタンの表示文言は本文の全3ウェイトに収録済み。
