# 成長直後の初回合奏を更新

相談・行事・冬の練習で部員やまとまりが変わっても、`U.perfNow`に変更前の音が残り、最初の合奏が古いまま鳴る場合があった。修正前のブラウザでは、相談後のまとまりが43でも再生は39の演奏。冬の練習後も新しい部から作った演奏と異なった。`before-consult.json`・`before-winter.json`にその比較を保存。

`commit`で次に聴く演奏を空にし、保存後の初回再生で必ず今の部から音を作る。`refreshNow`も描き直しを予約した時点で空にして、会場・範囲などを変えて20ms以内に押した場合を扱う。相談・行事・冬の練習・新体制の処理に診断と舞台の更新を追加。聴いている`U.shown`は差し替えず、停止後に現在の部へ戻る。採点・成長・音づくり・セーブ形式・音源は変更なし。

## 確認

- `check_live_performance.js`：実際のゲームの相談・行事・冬の練習・引退後の部を使い、実際の保存・更新・再生ボタンの処理を抽出。描き直しより早く押した再生が最新の演奏と一致。会場と範囲の即時変更、連続更新のまとめ、再生中の録音を保つこと、再生でセーブを変えないことを確認。
- 停止後の表示・席移動の取り消し・音源再試行・舞台の顔の既存の確認も実行。
- ブラウザの375px：相談・行事・冬の練習の選択から初回再生まで実際に操作し、演奏全体の比較が最新の部と一致。ライト・ダークで横幅375px。再生で部の状態を変えない。録音中に相談へ答えても、録音の演奏・名前・顔・保存済みの録音を保ち、停止後は今の部の演奏へ戻る。
- 通常の音源読み込みで一度`Failed to fetch`が発生。既存の「読み直す」で33個のバッファを保持して残り8個だけ再取得し、41個が揃った。再生は`SampleVoice`。この通信失敗の原因は今回の更新処理とは別で、未特定。
- `browser-check.json`に実画面の比較と状態を保存。確認ページは本物のセーブ・設定を書き換えない。画像は375×812のPNG。

画面の文章とフォントは変更していない。計算式も変えていないため、採点の全15曲の再調整は行わない。

後続の[起動調査](../boot-audit/README.md)で、ローカル配信の接続切断を再現して確認サーバーを改善した。ここで記録した通信失敗も、今後は起動前からの読み込み記録とともに確認する。
