# 起動時の色を、ゲーム内の紙色へそろえる

iOSの起動画面・WebViewの背景と、iOS側のアクセントが以前の配色のままだった。ゲーム内は承認済みの紙色と真鍮色になっており、起動時との色の差があった。

| 色 | ライト：以前 → 統一後 | ダーク：以前 → 統一後 |
| --- | --- | --- |
| Paper（背景） | `#ECEFF3` → `#F0EEE5` | `#0D1320` → `#12252F` |
| AccentColor（操作色） | `#A26F14` → `#936B2F` | `#DDAE55` → `#E7C38A` |

ネイティブの2個の色データだけを変更。色空間・不透明度・ライトとダークの分け方は維持した。承認済みの校章と音符のアイコンは60pxでも確認した。新しい画像・フォント・ダウンロードはない。

## 確認

- Webの`--paper`・`--brass`と、iOSのライト・ダーク4種類の色が一致。
- ビルドした実際のアプリの`Assets.car`を`assetutil --info`で読み、4種類の色が同じRGB・不透明度になっていることを照合。`compiled-colors.json`に保存。
- ビルド済み`Info.plist`の起動色が`Paper`を参照することを確認。SwiftUI・WKWebView・スクロール領域も既存の`Paper`参照を使う。アクセントもターゲットの既存の設定から参照する。
- 375pxのライト・ダークで配色比較を表示し、実際に描画したRGBが変更前・変更後の記録と一致。横にはみ出さず、アイコンは60px。ブラウザの警告・エラーなし。
- ゲーム本体のHTML・JSは今回変更せず、アプリ同梱物とも一致。前回の1年進行検証から同じゲーム本体を使用している。

`index.html`と`screenshots/`は配色プレビューで、実機の起動画面を撮影したものではない。プレビュー内にも明記。実機での起動から画面が出るまでの見え方はオーナー側で確認する。
