# 楽器の音を、その場で読み直す

- 音源を読めなかったときの合成音への切り替え表示に「読み直す」を追加。通常の合奏は一度止め、読めなかった録音だけ再試行する。読み直しただけでは再生せず、次に合奏を押すと録音で鳴らす。
- 読み込めたバッファ・処理済みの出だし・調律情報を再利用する。読み込みの処理がすべて終わってから再試行できるようにし、同じ処理を重ねない。HTTPのエラーを中身の展開前に扱い、HTTPの状態が0の応答は従来どおり中身を読めれば使う。
- 本番の発表前や指揮・本番の舞台中は、この操作で止めない。ゲームの保存・採点・成長、音量、調律や出だしの式、音源ファイルは変更なし。素材の取得や音源の作り直しなし。

## 調査と確認

以前のブラウザ確認では音源を読めず合成音になる表示が出ていた。今回の通常読み込みでは41音源とも正常で、以前の一時的なエラーの原因は特定できなかった。一度エラーになると、終了した読み込みのPromiseを返し続けて読み直せないことをコードで確認し、復旧の操作を追加した。

- 確認ページだけでフルートの1回目をHTTP 503にする。40音源は正常に読み込まれ、合奏はWindVoiceで鳴る。「読み直す」の後は41音源がそろい、SampleVoiceで鳴る。
- 読めていた40音源のオブジェクトが同じままで、要求回数はフルートだけ2回、目録とほかの録音は1回。読み直しだけでは再生せず、前後でセーブの内容も不変。
- 通常の読み込みは41音源とも成功。再び読めない場合でも40音源を保ち、再試行できる。
- 375×812のライト・ダーク、横はみ出し・確認中のJavaScriptのエラーなし。画像は確認用のエラーを起こした見本。確認ページは実際のセーブを書き換えない。
- check_sample_retry.jsでHTTP・音の展開・目録のエラー、状態0の応答、処理中の二重実行、残りの読み込みとの競合、既存バッファと調律情報、繰り返すエラー、本番・指揮を中断しない操作を確認。席の取り消しの回帰確認も実施。
