# 曲を選びながら、聴いて止める

## 見つかった不具合

部員一人の音を聴いた後で選曲のお手本を押すと、実在の部員idの指定が残り、お手本の部員に該当せず無音になっていた。また、表示は県民文化会館でもエンジンは音楽室のまま。同じボタンを押しても停止せず、最初から再生し直していた。`before.json`に記録。

## 変更

- `listenPiece`で前の音と終了処理を片づけ、全員の音へ戻してから選んだ曲を再生する。お手本では実際の会場もホールへそろえる。
- 再生している曲のカードと、押した聴き方のボタンに金色の枠を付ける。同じボタンは「止める」へ変わり、もう一度押すと停止する。読み込み中も同じボタンで中止できる。
- 自然終了で元の印へ戻す。候補・聴き方を切り替えたら古い待機を中止し、後から重ねて鳴らさない。
- 選曲の確定や部を保存する操作では古い試聴を止める。曲の一覧をスクロールしても、小さな再生バーから止められる。

お手本の演奏内容、採点・成長・ゲームの選択処理・セーブ形式は変更していない。会場の操作は既存の設定に従い、お手本の後はホールが現在の会場になる。新しい絵・フォント・動く演出・外部取得は追加していない。

## 確認

- `check_piece_listening.js`で全15曲×お手本・いまの部の30通りを実際の演奏と照合。本人指定の解除、会場、停止、切り替え、自然終了、読み込み待ちの中止、古い予約の破棄、再生失敗時の印、部を保存したときの停止も確認。
- 実ブラウザで、個人試聴の後のお手本が全員で鳴り、実際の会場がホールになることを確認。いまの部では現在の5人または39人の音だけになる。再生・待機の演奏ハッシュを期待した演奏と照合した。
- 自由曲・課題曲・定期演奏会の選曲を確認。確定した部のハッシュは従来のゲーム関数へ同じ選択を渡した結果と一致。確定時には音と待機を止め、解放後も古い曲が鳴らない。
- 375×812と375×667のライト・ダークで横にはみ出さず、操作は44px以上。読み込み中も3列の中に収まる。スクリーンショットは実画面の現在のスクロール位置から撮影した。
- オーディションの試聴、現在の演奏、席移動の取り消し、アンサンブル試聴の既存検証も合格。各`*-check.txt`に記録。
- 49操作で2027年度へ進行。33スクリプトの起動に成功し、コンソールの警告・エラーなし。
- 字の検査は既存の5記号（▶♩♮⤓𝄪）とコードコメントの「常」「了」を報告。今回の表示と読み上げ文言は本文の全3ウェイトに収録済み。

`browser-check.json`は各操作直後の観測。`model-restart`・`own-restart`は前の曲が終わった後の再生で、停止の証拠には使わない。`confirmed-toggle-stop`・`set-toggle-stop`で再生中の同じボタンによる停止を確認した。

- `natural-final-before`から`natural-final-after`で実際のお手本が自然終了し、音・待機・再生中の印が消えることを確認。部と録音は不変。
