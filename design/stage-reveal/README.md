# 再生したら、舞台が見える

合奏の診断を読んだ位置から「いまの音で合奏」を押しても、舞台は画面外に残っていた。再生ボタンが消えた後の操作先もbodyへ落ちていた。変更前の375×667では、診断の位置のスクロールが1,125px、舞台の下端は画面上の−680pxほど。`before.json`に記録。

## 変更

- メインの合奏を直接始めた場合は、停止ボタンへ操作先を渡す。
- 小さい画面で舞台が画面外や下の操作に隠れている場合だけ、曲名と舞台を見渡せる位置へ戻す。安全な余白を取り、動く演出は加えない。すでに舞台が見えていればスクロールしない。
- 部員カードなどからの試聴は、カードとその操作先を保つ。直接の操作とプログラムでの再生を区別する。
- 読み込み待ちでも舞台と停止を見せ、再生できなかった場合は動かさない。

画面の文言・顔・楽器・音・成長・採点・録音・セーブ形式を変えていない。追加の素材やダウンロードもない。

## 確認

- `check_stage_reveal.js`：メインの実際のイベント処理と表示処理の10通りを確認。舞台の上・下へのはみ出し、見えている場合、カードからの再生、待機、再生失敗、広い画面、別タブを区別。同じ演奏を一度だけ鳴らし、部と音を変えない。
- 実ブラウザ16状態。375×667の診断の位置から再生するとスクロール2pxへ戻り、舞台全体が下の操作より上へ収まる。39人の顔を維持。最初から見えている舞台は0pxのまま。
- 再生後は停止へ、停止後は再生へ操作先を保持。キーボードでも再生・停止・再生ができる。ライトとダークで同じ演奏idを保つ。
- 部員カードの試聴は、カードのボタンへ操作先を置いた状態で前後のスクロール350pxを保持。本人とパートを切り替えても舞台へ飛ばない。
- 待機中も診断の位置から舞台へ戻る。中止で再生ボタンに戻り、音源を解放しても古い待機は鳴らない。
- 部と録音のハッシュ、表示する演奏と現在の演奏の対応を照合。49操作で2027年度へ。33スクリプト起動成功、4タブ375px、コンソール警告・エラーなし。
- 本人の試聴、停止後の操作先、選曲の試聴、お手本の文脈、再生バーなど6種類の既存検証も合格。表示する文字は変更せず、字の検査は既存の記号とコメントの8字を報告。
