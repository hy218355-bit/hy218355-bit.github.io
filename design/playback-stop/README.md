# 止めた録音の音量を、後の指揮で戻さない

指揮した録音を途中で止めると、停止のフェードより後に予約されている`conduct.lv`の強弱で、古い再生の音量が再び上がっていた。停止は既に滑らかな減衰を使っていたが、未来の強弱予約を取り消していなかった。

`Playback.stop`で、直接音と残響の出口の予約を取り消し、現在の音量に開始点を置いてから、従来の時定数0.04秒で減衰させる。`cancelAndHoldAtTime`がない環境も、直前の音量を保つランプを使う。通常の停止も同じ処理にそろえる。

音源の停止は従来の0.3秒後、出口の片づけは800ms後。二度停止しても処理は一度だけ。自然終了の`finish`は変えず、余韻のための4秒の片づけも保つ。指揮の判定・強弱・録音・採点・成長・セーブ形式・画面の文言は変えていない。新しい素材・演出・ダウンロードはない。

## 実音声での確認

`probe.js`は製品の`Playback.stop`と`setLevel`を呼び、48kHzの`OfflineAudioContext`へ、直接音と残響を別チャンネルで書き出す。音源の停止時刻も実際と同じ0.3秒後にする。この確認ページからスピーカーへ音は出さない。

- 変更前の`baseline.json`では、停止後に再上昇がある。`screenshots/pcm.png`の桃色はその書き出し値、緑色は修正後。点線が停止の瞬間。
- 停止の時刻0秒・0.12秒・0.28秒、強弱予約の有無、標準と互換処理の12条件。直接音・残響とも停止後の再上昇なし。切れ目は通常の1サンプル相当以内、音源の停止後は0。
- 同じ停止を二度呼んでも、音源を止める回数と終了時刻は一度分のまま。
- `finish`の比較では、後の強弱と音を残し、停止のフェードを自然終了へ混ぜていない。
- `pcm-check.json`へ実測値を保存。ケースごとに開始点・1サンプルの差・最大の再上昇・音源停止後・音源の停止回数を記録する。
