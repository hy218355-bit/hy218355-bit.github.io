# 顔と希望を見ながら、楽器を決める

- 入部の札を40pxの顔、名前と経験、楽器のアイコンと希望、現在の席の順に整理。選択中は金の枠と淡い背景にした。
- 担当選びには48pxの顔と名前、現在の席を表示。前後の部員へ移る44pxのボタンを設け、375pxでは選択した本人の担当欄へ移動する。動きを減らす設定と演出設定に従う。
- 楽器ごとの席を名前の付いたボタンで選べる形にした。本人の席と空き席だけを表示し、先輩や別の新入部員と重ならない。席は58px以上、パートの見出しは48px。選択は金の枠・塗り・チェックと `aria-pressed` で示す。
- 希望と現在の担当のパートを開く。同じ部員について手で閉じたパートは、席を選び直しても閉じたまま。状態は画面内だけに持ち、セーブには追加しない。
- 舞台は「舞台で見る」に折りたたんだ。席の位置とタップの判定は従来どおり。楽器は既存の自作アイコンで描き、色は名前のある色から取る。説明は吹き出しへ移した。
- 控えと決定の46pxのボタンを下のタブのすぐ上に置き、再生バーがあるときも避ける。
- 自動配置・入部処理・初期能力・希望によるやる気・顔の配役・ゲームの点数や成長・セーブ形式は変更なし。素材・フォントのダウンロードなし。

## 確認

- 375pxのライト・ダークで入部と担当選び、先輩がいる入部、満席、優秀な経験者を確認。4タブの両テーマもスクリーンショットを保存。横幅はすべて375pxに収まる。
- 最初の配置が従来の `autoAssign` と一致。部員を前後に切り替えても配置は変わらない。
- 控えにすると席が空く。キーボードでも席を指定でき、ほかに席のない部員がいればその子を選ぶ。決定後の名前・席・希望は従来の `assignRecruits` の結果と一致し、週は進まない。
- 先輩32人とほかの新入部員の席は選択肢に出ない。39席すべてが埋まっている場合も、元の39人の席を変えず、新入部員8人を控えとして決定できる。
- パートの開閉状態の維持、楽器決めの吹き出し、舞台の表示を確認。
- 4月から新年度まで49回の画面更新で2027年度へ進み、画面確認中のエラーなし。日誌80件の文章も保持。
- JavaScriptの構文、顔と名前・画像の再利用・舞台の位置の既存チェック、`git diff --check` が成功。字のチェックは既存の不足記号5字だけで、新たな不足なし。
- iPhoneにビルド・インストール・起動が成功。アプリ内の `index.html` と `js/ui.js` は作業中のファイルと同一。実機の見た目はオーナーが確認する。
