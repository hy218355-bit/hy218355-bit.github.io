# 指揮画面の操作を画面内へそろえる

指揮のタップ面からTabを押すと、裏の「今週」へ移っていた。閉じたあとも、非表示になった「やめる」へ操作先が残っていた。また、本番の説明を開いてEscapeを押すと、説明と一緒に本番も閉じていた。修正前の実際の操作は`before.json`へ記録。

## 変更

- 指揮・本番の画面をダイアログとして示し、裏のアプリ・タブ・再生バーは開いている間だけ`inert`にする。元からの状態を覚え、閉じると戻す。
- Tab・Shift+Tabは画面内で循環。通常の指揮はタップ面、本番を聴く画面は「とばす」から操作できる。閉じたら元の操作へ戻し、本番の操作が作り直された場合は「結果を見る」などの次の操作へ戻す。
- 説明が開いているときのEscapeは説明だけを閉じる。次のEscapeで指揮・本番を閉じる。キーを押し続けた場合や日本語変換中は閉じる処理を重ねない。
- 演奏後にタップ面が消えたら、結果の見出しへ操作先を移す。保存の知らせと最終の保存ボタンも同じ画面内に置き、書き出しを押せなくしない。
- 説明は押した部品と`aria-describedby`で結び、指揮中の説明は同じ画面の中へ置く。通常画面では元どおりページ上に出す。画面の文章・採点・成長・セーブの形には変更なし。

## 確認

Chrome・375pxのライトとダークで実際に操作した。

- タップ面→Tabで「やめる」→Tabでタップ面を4回確認し、裏の画面へ出ない。Shift+Tabも本番の説明ボタンから循環する。閉じたら「指揮する」へ戻る。
- 本番の説明を開いてEscapeを押しても、舞台を開いたまま保つ。実際のA部門コンクールでも、課題曲の演奏が続き、未発表の状態と部員・録音の内容が同じであることを確認。
- 課題曲が自然終了し、自由曲のテンポ出しへ切り替わってもタップ面に操作先があり、裏の画面は操作できない。閉じると「結果を見る」へ戻る。
- 実際の4回のテンポ出し・4回のタップはすべて「ぴったり」。自然終了で録音1件が残り、「演奏おわり」へ操作先が移る。次のTabで「もう一度聴く」を選べる。
- 実音の録音を書き出し、最終の「保存する」まで作られること、そのボタンをTabで選べることを確認。ファイルのダウンロード・共有は実行していない。
- 読み込み待ちでも中止でき、読み込みが終わってから開き直すとテンポ出しへ進む。閉じた後の通常画面の説明も開閉できる。
- 指揮から確認用の別画面へ切り替えた後、4月から新年度まで49操作で2027年に到達。裏の操作制限が残らず、起動33/33・コンソール警告とエラーなし。
- 入力待ちの補正・拍・保存した指揮・全15曲の区間とテンポ変化・動きを減らす設定の回帰確認を実行。字の確認は以前からの未収録5記号のみ。新しい素材・フォント取得なし。
- Release版をiPhoneへ導入し起動。ミラーリングなしで実行プロセスと3ファイルの同梱一致を確認。実機の画面・音・操作感と読み上げはオーナー側で確認する。

`browser-check.json`、`console-check.json`、`iphone-check.json`、回帰確認のテキストとPNGへ記録。操作先を読む診断は確認ページだけに置き、製品には入れない。
