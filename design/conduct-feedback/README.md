# 指揮の判定を見やすくする

B案の低いタップ面に、以前の上へ飛ぶ判定の表示が残っていた。375×812で実際に叩いたところ、「ぴったり」の判定の表示枠の高さは操作面に約35％しか入らず、残りは上端に切れていた（`before.json`）。

判定を操作面の外、合図の上へ固定した。判定用に24pxの高さを確保し、光・指・ボタンの文字と重ねない。判定は同じ1要素を使い回す。タップのたびに広がってボタンを隠す円もやめ、面の色が120msだけ反応する形にした。4拍タップしないと古い判定を消し、再開すると通常の案内へ戻す。中止・終了・開き直しでも消す。

## 確認

- Chromeの375×812、375×667、ライト・ダークで確認。判定は常に枠の外で、合図より上に完全に収まる。文字の表示は1個、旧来の円と飛ぶ文字は0個。横にはみ出さず、タップと下のテンポが画面内に収まる。
- 実際の4回のテンポ出しと4回のタップで、4回とも「ぴったり」。41音源を読み込み、`SampleVoice`で演奏する。速さ・判定幅・指揮の効き・保存形式は保つ。
- 4拍の休止で判定が空になり、再開では新しい判定と通常の案内へ戻る。左上を触っても同じ場所に表示し、強弱は従来どおり変わる。中止と開き直しで文字が残らない。自然終了でも消え、録音1件へ進む。
- 入力待ち・保存した指揮・全15曲の区間とテンポ変化・2/3/4/8拍・演出なし／短く／動きを減らす設定の回帰確認を実行。CSSの判定表示は全設定で移動アニメーションなし。
- コンソールの警告・エラーなし、起動33/33。字の確認は以前からの未収録5記号のみ。新しい素材・フォントの取得なし。
- Releaseビルド・iPhoneへの導入・起動を確認。ミラーリングを使わず、実行プロセスと変更ファイルの同梱ハッシュも確認済み。実機の画面・音・操作感はオーナー側で確認する。

`browser-check.json`・`console-check.json`・`iphone-check.json`とPNGへ記録。判定位置の計測は`judgeAudit=1`を付けた確認ページだけで、ゲームとセーブには入れない。
