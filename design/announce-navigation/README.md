# 結果発表から次の行動へ戻れるようにする

発表をとばした後は操作先がbodyに残り、Tabで裏のボタンへ移れていた。結果画面はdialogとしても扱われず、裏のアプリとタブが操作可能な状態だった（実画面の`before.json`）。

## 変更

- 結果発表をdialogとして扱い、裏のアプリ・タブ・再生バー・ほかの重なる画面の元の`inert`を覚えて操作を止める。閉じたら元の状態へ戻す。
- 発表開始時は「とばす」、表示が終わったら「結果を見る」に操作先を置く。演出なし・手動スキップ・自然終了で同じ処理を使う。
- 一覧へTabで移り、矢印・Home・Endで結果を読み返せるようにする。一覧と操作ボタンの間でTab・Shift+Tabが循環し、裏へ抜けない。操作先は既存の金色の枠で示す。
- Escapeは発表中なら残りを表示し、表示済みなら閉じる。同じキーを長押しした繰り返し入力や変換中の入力で、二段階を続けて実行しない。
- 閉じたら元の操作か結果の次の行動へ戻す。古い画面への復帰が、開き直しや次の画面の操作先を奪わない。閉じる処理を二度実行しない。
- 点数・賞・代表・学校の発表順・待ち時間・顔・セーブ形式は変更しない。通常表示の文章を増やさず、一覧の読み上げ名だけを付ける。素材・フォントの取得なし。

## 確認

- 375×812のライト・ダークで金賞と銀賞を確認。「結果を見る」は高さ46px、横にはみ出さない。本人の顔8人も従来どおり表示する。
- Tabで一覧へ、Endで一覧の下まで移動し、Tabで「結果を見る」へ戻れる。裏のアプリ・タブはinertで、閉じたら元へ戻る。
- 演出ふつうの途中からEscapeで12校の結果を表示し、結果画面は残る。もう一度のEscapeで閉じ、確認用の終了処理は1回だけ。900ms保持した入力でも、表示した結果まで閉じなかった。ただしブラウザの記録にrepeat入力は発生していないため、繰り返し入力の防止そのものは下の単体確認で検証した。
- 375×667の両テーマでB部門の銅賞を確認。短い演出を自然終了させると「結果を見る」に操作先があり、代表校の表示はない。ボタン下端653pxで画面内。動きを減らす設定の分岐と演出の時間は維持する。
- 実際に3年目のコンクールまで進めた結果を表示し、閉じると「シーズンを終える」へ操作先が移る。審査結果全体・部員・録音の指紋は表示前後で一致する。
- 結果を閉じて、375pxのライト・ダークで4タブを操作。さらに確認用の発表から別画面へ移り、50進行で4月から新年度2027年へ到達。操作制限は残らず、起動33/33、エラーなし。
- `check_announce_navigation.js`で、繰り返し・変換中の入力、Tab循環、閉じる処理の一回実行、元からinertだった画面の復元、閉じた後の開き直しと操作先の競合を確認（`navigation-check.txt`）。指揮の予告・入力時刻と保存した指揮の既存の回帰確認も成功（`cue-check.txt`・`timing-check.txt`）。
- 字の確認は既存の未収録5記号のみで、新しい不足なし（`glyph-check.txt`）。
- Release版をミラーリングなしでiPhoneへ導入。HTMLと結果発表コードの同梱ファイルは一致。端末がロック中のため今回は起動と実行プロセスは未確認（`iphone-check.json`）。実機の画面・音・操作感はオーナーが確認する。
