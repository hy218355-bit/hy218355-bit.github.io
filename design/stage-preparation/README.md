# 本番の前に、3つだけ確かめる

## 変更

- 本番まで3週以内の練習と、本番当日に、人選・譜読み・体力の3つのカードを表示。詳しい情報は、押した項目だけを開く。
- 人数は実際に出る部員で数える。コンクールでは選んだメンバー、演奏会ではコンクールの控えも含む全員。席のない部員は含めない。人選を変える操作は従来のオーディションへつなぐ。
- 譜読みは出場者の平均をG〜Sで表示し、低い部員から顔と名前を並べる。A部門のコンクールでは課題曲・自由曲を分け、演奏会では自由曲だけを表示する。
- 体力が低い出場者を顔で確認できる。出ない部員を含む部全体の疲れも、実際の演奏に使う条件から表示する。
- 練習週は顔から本人の指示を選び、選択後に元の準備欄へ戻れる。体力の顔からは「休む」を先頭側へ。本番当日は確認だけにし、練習できるように見せない。
- 会場・本番・ライバル・指揮の文章は「会場と本番」で開く形にまとめ、本文は保持した。本番の種類を同じ画面で繰り返す札は省いた。
- 演奏開始と指揮はスマホの画面下に固定。録音などの再生中の小さなバーとは重ねず、ほかのタブには出さない。
- 舞台袖で緊張する部員に顔を添え、声かけと全員の深呼吸は44px以上で押せるようにした。回数と効果はそのまま。

変更は表示と操作位置のみ。点数・成長・人選・演奏・声かけの効果・セーブ形式は変更なし。準備の開閉はUIのメモリだけで持つ。既存の顔と自作SVGを再利用し、素材やフォントの取得はしていない。

## 確認

実ゲームと同じ画面とスクリプトを使い、確認ページだけはセーブと設定の保存を止めた。最終版は`qa-stage-preparation-3`。

- `browser-check.json`に33場面を保存。375×812のライト・ダークで概要、2曲の譜読み、体力、舞台袖を確認。
- コンクールの34人の準備と、実際に始めた課題曲・自由曲の録音各34人のidが一致。譜読みの平均も出場者だけの元データから計算して一致。
- 演奏会はコンクールの控え4人を含む38人。A部門で課題曲がある場合も自由曲だけを表示し、実際の録音の38人と一致。席のない1人は含めない。
- 準備の3項目を開いても、部・能力・録音の状態はそのまま。Escapeで閉じ、押した項目へフォーカスを戻せる。
- 練習週に体力の顔から本人のメニューを開く。見るだけでは指示を変えず、「休む」の決定で指示だけが変わる。戻ったときも元の顔と体力の項目が開いている。
- 本番当日の譜読み・体力の顔には練習を選ぶボタンを出さない。声をかける・全員で深呼吸するの2回を実行し、それ以上は押せない。能力は不変。
- 全員を控えにした0人の状態から、人選を開いて38人へ決め直せる。舞台袖のデータがない前の状態でも準備は表示できる。
- 出場者1人の体力は十分でも、部全体に疲れが残る場合は、そのことを表示する。準備欄の疲れの条件と、実際の録音に保存された条件が一致。
- 320×568でも横幅320px。開始・指揮の両ボタンは48pxで画面内にあり、下のタブバーに重ならない。
- 小さな再生バーがある間も開始操作と重ならず、実際に開始ボタンを押せる位置。4タブ×両テーマで横幅375px、固定の操作は今週だけ表示。
- 初年度を実際の69操作で2026年4月から2027年4月へ進行。41場面で次の本番の対象者を照合し、エラーなし。コンソールの警告・エラー0件。
- 顔100人・舞台の顔と楽器・個人録音の停止・卒業の保存と移動の既存確認が成功。構文・差分も問題なし。字形チェックは既存の不足記号5字のみ。

年度の進行と対象者は`year-flow.json`、4タブは`tabs-check.json`、コンソールは`console-check.json`。PNGは1枚200KB以内。通常375×812、小さい画面だけ320×568。
