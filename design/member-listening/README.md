# 本人とパートを、そのまま聴き比べる

## 見つかった不具合

本人だけを聴いているときに同じボタンを押しても、全員へ戻らなかった。停止しても本人の`aria-pressed`がtrueのまま残り、再生中に見えた。`before.json`に記録。切り替えのたびにカード全体も作り直され、未保存の名前の入力欄を保てなかった。

## 変更

- 本人・パートのボタンをもう一度押すと、再生を続けたまま全員の音へ戻す。別のボタンで本人とパートを切り替える場合も再生位置を保つ。
- 現在の部の演奏と対応する再生・待機の間だけ、金色の面とチェックを付ける。読み上げにも現在の対象と解除の操作を示す。停止・自然終了・待機中止で印を戻す。
- 止めた後の聴く対象の設定は保ち、次に同じボタンを押すと本人の試聴を再開する。
- 同じ部員の情報ならボタンだけを更新し、カードとボタンを作り直さない。成長・思い出の開閉、未保存の名前、操作先を保つ。部員の情報が変わった場合は描き直して最新の力を表示する。
- 「全員の音にもどす」もボタンを残して表示だけ切り替え、押して隠れるときは本人のボタンへ操作先を戻す。

部員・顔の配役・力のランク・採点・成長・音・録音・セーブ形式は変えていない。カードの対応はUIにだけ持つ。画面の説明文・素材・フォント・動く演出の追加、外部取得はない。

## 確認

- `check_member_listening.js`で全15曲×本人・パートの30通りを確認。選択・再タップ解除・切り替えで再生と演奏を保ち、部を変えない。ボタンと入力・開いた内容の保持、停止後の印と再開、待機を保った全員への復帰、違う演奏と成長後は最新の部へ切り替えること、録音と控えの区別を確認した。
- 実ブラウザで本人1人→全員39人、パート4人→全員39人、本人とパートの切り替えを確認。同じ再生idと演奏ハッシュを保持。停止後は選択の印が消え、次の本人のタップで再開する。
- QAのWeakMapでボタン自身へ番号を付け、最初の表示から選択・切り替え・停止・再開・解除まで同じ3ボタンを使うことを照合。
- 成長と思い出を開き、名前を未保存で入力してから本人→パート→全員へ切り替えても、開いた内容と入力文字が残る。部の名前は保存していない。
- 自然終了で本人の印を解除。聴く対象の設定はそのまま。375×812と375×667のライト・ダークでボタンは44px以上、横にはみ出さない。
- 待機中のパートの再タップで全員へ戻り、本人を選び直して中止すると印を解除。音源の解放後に古い待機は鳴らず、本人を押すと再開できる。
- 49操作で2027年度へ進行。4タブにはみ出しなし。33スクリプトの起動に成功し、コンソール警告・エラーなし。
- 現在の本人、オーディション、録音カード、個人録音の停止、お手本の文脈、停止後の操作先の既存検証も合格。各`*-check.txt`に保存。
- 字の検査は既存の5記号（▶♩♮⤓𝄪）とコメントの「常」「了」「奪」を報告。表示するボタンの文言は変更していない。

`browser-check.json`は各操作直後の観測、`browser-assertions.txt`は状態・対象・演奏・ボタンの対応の照合。QAは本物のセーブと設定を書き換えない。
