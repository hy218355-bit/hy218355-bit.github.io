# 部員を見ても、舞台の表示を保つ

舞台や名簿で部員を開くたびに、`U.view`がその部員のパートへ自動で切り替わっていた。カードを閉じても戻らず、舞台のほかの部員が薄いまま残り、たたんでいた「音の動き」の表示も変わっていた。

カードを開く2か所から自動切り替えを取り除いた。選択中の顔と楽器の印は表示し、元から見ていた範囲を保つ。「音の動き」と「パートのようす」で選ぶ操作はそのまま使える。閉じる前に自分で表示を変えた場合は、その選択も保つ。

音・採点・成長・セーブの処理、画面の文章、絵、フォントは変更なし。確認用ページだけ、画面幅を変えたときにも記録を更新するようにした。

## 確認

- 修正前は旋律表示`mel`からフルートの本人を開くと`fl`へ変わり、閉じても`fl`のままになることを画面で再現した。`beforeInitial`・`beforeOpened`・`beforeClosed`が記録。
- 修正後は375pxライト・ダークで、開く前・開いている間・閉じた後も`mel`を保持。周りの部員を薄くしない。
- 手動でトランペットを表示してからフルートの本人を開いても、`tp`を保持。途中でクラリネットへ変えて閉じると`cl`を保持。表示外の本人の選択の印も見える。
- 「パートのようす」でトランペットを選ぶと従来どおり表示が切り替わり、同じパートをもう一度押すと元へ戻る。
- 現在の合奏を聴きながら舞台と名簿のカードを開閉。再生のid・全員の試聴指定・演奏全体のハッシュが変わらず、音を作り直さない。
- 名簿を2年・名前「悠」で絞ったまま本人を開閉し、表示範囲・検索条件・戻る行のフォーカスを保持。部の状態・能力・録音は不変。
- 昔の録音で改名・席替え前の本人を開いても表示範囲を保持し、再生が続く。現在の合奏に切り替えると今の本人の名前を表示。録音と現在の演奏のハッシュも従来の生成処理と一致。
- 320pxの端の部員、控え、空席でも確認。4タブ×ライト・ダークで表示範囲と選択を保持し、横はみ出しなし。
- 画面とコンソールのエラーなし。33スクリプトの読込成功。構文・差分の確認成功。
- iPhone用Releaseビルド成功。初回はオーナーの「あとで確認する」に合わせて実機操作を保留。その後の「実機」の依頼で、最新版`9a45c1b`をiPhoneにインストールし、起動成功と起動中のプロセスを確認した。同梱したHTML・ui.js・conduct.jsが作業フォルダとSHA-256で一致。端末上での画面操作は未確認。

記録は`browser-check.json`・`console-check.json`・`iphone-check.json`。確認ページは本物のセーブと設定を書き換えない。画像は実際の375×812px、320×568pxの画面をPNGで保存し、表示内容は加工していない。
