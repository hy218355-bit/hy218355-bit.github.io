# 端末の保存が終わるまで、次の保存を重ねない

変更前はWAVの受け渡しが終わると保存中の扱いが消え、iPhoneでのAAC変換や共有シートを待たずに別の保存を始められた。`baseline.json`では完了通知が0件なのに保存ボタンが有効へ戻っている。

`deliverFile`はファイルごとのidを付け、Swiftの`onNativeFileDone(ok,id)`が返るまで待つ。録音とセーブを同時に送らず、古いファイルの通知は無視する。成功・失敗・送信の例外で待機を外し、途中で失敗した場合は残りのかたまりを送らない。

保存中の録音は金色の印と`aria-busy`で示し、保存ボタンを一時的に止める。演出ふつうだけ印を回し、短く・なし・動きを減らす設定では静止する。指揮結果の保存ボタンも同じ待機を使う。結果を閉じても保存を重ねない。

知らせは中央のまま内容に合った幅へ広げ、不自然な折り返しを減らした。ブラウザの「保存する」は44px。表示する説明は増やさず、音・採点・成長・部員・録音・セーブ形式は変えていない。待機はUIのメモリだけに持ち、保存コードへ足さない。画像・フォントの追加やダウンロードもない。

## 確認

- `check_native_file.js`で8分割の順序とid・全バイトの一致、完了まで待つこと、重複送信の拒否、古い通知、成功・失敗・送信の例外、録音を二重に作らないこと、本人だけの書き出し、途中失敗時の送信終了を確認。
- ブラウザでは本物の録音とWAV書き出しを使い、端末への受け渡しだけ確認用の窓口へ置き換えた。iPhoneの共有シートを実際に操作した記録ではない。
- 375pxのライト・ダークで待機中・古い通知・完了・失敗・再試行を確認。ボタンの印と44pxの大きさ、知らせと下の操作が重ならないこと、部と録音のハッシュが不変なことを照合。
- 演出ふつうは回転、短く・なしは静止。動きを減らす端末ではCSSの`prefers-reduced-motion`でも回転を止める。
- 指揮結果でも保存を待ち、結果を閉じた後の完了で待機を外す。ブラウザの保存案内は結果画面の中に残り、44pxの保存ボタンが画面内に収まる。確認のために実際の共有先への送信やダウンロードはしていない。
- 49操作で2027年度へ。33スクリプト起動成功、警告・エラーなし。コードの39検査も成功（`../final-audit/checks.json`）。
- 字の検査は従来からの10字を報告。5つは意図的に端末の標準フォントを使う音楽記号などで、残りはコードのコメント。表示文章を追加していないためフォントは変えていない。

記録の照合：`python3 design/native-export/check_results.py`。各状態のJSONと`screenshots/`へ実画面を保存。確認ページは本物のセーブと設定を書き換えない。
