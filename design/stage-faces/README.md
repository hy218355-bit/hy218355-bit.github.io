# 素朴な30人と、演奏の顔表示

2026年10月26日。オーナーの「それ以外も可愛くなってる」「演奏も顔出たらいい」を反映した。別worktreeの `codex/design` で作業し、pushしない。

[画面を見る](index.html)

## 顔

- かわいい女子8人・かっこいい男子1人に使う `portraits-01.webp` は、ファイル内容を変えず保持。
- ほか30人を新しく描き直した。小さめの自然な目、平らな眉や太い眉、丸顔・面長・幅のある輪郭、鼻と口の違い、普通の髪型と控えめな表情を指定。幼い高1の年齢感と、線や色のなめらかさを保つ。
- 女子23人・男子7人を3枚に分けて制作。全体は前回と同じ39人。名前と顔の配役、idでの選択、名前生成、既存セーブは変更しない。
- 新原画は組み込みimage_genで制作（CLI不使用）。[最終プロンプト](prompts.json)、[原稿と圧縮の記録](../../tsukurikata/img/faces/manifest.json)。元の画素数を保ったWebPで、各画像200KB以下。外部素材・ダウンロードなし。

## 演奏

- 合奏・本番・指揮の舞台に、カードや名簿と同じ顔を表示。375pxでは約31〜34px。音の左右の位置や座席データは変えず、見た目を奥行き順の5段にして、顔を大きく並べた。
- G〜Sの色を外周に残し、1年生の白い輪、音量に応じた光、ずれた音の赤い光、選んだ部員の枠を維持。能力の数字や新しい説明文は追加しない。
- 顔の位置とタップ位置を共通にし、既存の部員カードへつなぐ。本番の「この子の音だけ聴く」を顔の近くへ移動。カードが長いときは画面内をスクロールでき、「とばす」は上に残る。
- 昔の録音は録音に入っているidで顔を選び、同じ席の別の現部員を出さない。卒業生の録音の席を押して、同じ席の現部員のカードが開くことも防いだ。
- 原画は4枚だけ読み込み、原画ごとに128pxの丸い画像を1回作る。毎フレームはその画像を使い回す。新しい動きは足さず、本番のカードへのスクロールは動きを減らす設定と「演出：ふつう／短く／なし」に合わせる。

## 確認

- `node tsukurikata/tools/check_faces.js`：39人の内訳、名前との対応、名前生成が元のまま、セーブ不変、キャッシュ・画素数・容量。
- `node tsukurikata/tools/check_stage_faces.js`：240〜720pxで顔が重ならず舞台に収まる、全39席のタップが一致、楽器決めの配置を維持、昔の録音が本人の顔になる、同じ顔を100回描いても原画の読み込みと丸い画像の生成は1回、全原画でも4枚・39個を上限に再利用。
- 375×812、ライト／ダークで合奏・本番・部員カード・一覧・今週・相談・卒業式・入部の16画面。横幅375px、エラーなし。[記録](screenshots/checks.json)。
- 合奏と本番のキャンバスで、39人の顔の描画を確認。実際に39人で音を再生し、再生中も39人を描画、停止までエラーなし。指揮の画面でも39人の顔と、画面内のタップ面を確認。
- 本番の顔を押し、同じ部員のカードを開く。音を聴くボタンは637〜674px、上の「とばす」も画面内。ライト／ダークの画像を保存。
- 4月から翌年4月まで50回進行し、2027年度・セーブv2へ到達。コンソールエラーなし。[記録](screenshots/year.json)。
- 今回は同じ確認ページ内でキー操作によって画面とテーマを切り替えた。前回のように、画面ごとにスクリプト・録音素材を読み込み直していない。確認用キーは `design/implementation/qa.js` のみで、ゲームやiOSへは同梱しない。
- JS構文、`git diff --check`、文字確認を実施。不足は従来の操作・楽譜用5記号のみ。点数・成長・イベント・楽器・曲・音の処理と、整った9人の原画には差分なし。
