# 本人の録音を止めた後の聴き方をそろえる

引退前の部員を開き、入部時と最後の本番を本人の音だけで聴き比べる操作を確認した。

## 再現した問題

- 音源の読み込み待ちで停止すると、本人だけの指定が残った。次に普通の合奏を始めると「全員」と表示していても一人だけ鳴った。
- 本人の録音から全員の録音へ切り替えると、前の終了処理が呼ばれず、やはり一人だけ鳴った。
- 本人の録音を再生しても、合奏の聴き方には「全員」が残った。

`before.json`は修正前の実際のボタン操作。次の合奏や全員の録音でも、本人一人だけが再生対象になっている。

## 修正

読み込み待ちに中止専用の処理を持たせ、本人の録音では停止と同じ後片付けを行う。本番の終了処理は待機を中止しただけでは呼ばない。録音の切り替えは、前の再生を終えてから新しい会場と音を準備する。別の本人へ切り替えた場合は、新しく選んだ本人を保つ。

聴き方の本人名は、現在選択しているカードだけでなく、待機中・再生中の録音の部員からも取得する。表示と実際の再生対象をそろえる。

点数・伸び方・音源・顔・セーブ形式・画面の文章は変更なし。録音の本人比較は引退直前の画面にあり、卒業後に個別の再生ボタンを足したものではない。

## 確認

`browser-check.json`に375×812での実操作10場面を保存した。

- 読み込み待ちを停止して全員の指定へ戻る。読み込み完了後も勝手に鳴らない。
- 再生中の本人から全員の録音へ切り替えると39人が再生対象になる。
- 待機中に別の本人の録音へ切り替え、完了後は新しい本人だけが鳴る。
- 聴き方は本人の名前、会場は実際の録音会場と一致。
- 3年生13人の引退を画面操作で進め、名簿が26人になった後の卒業式でも録音時の39人が再生対象になる。
- ライト・ダークとも横幅375px。33本のスクリプトを取得し、起動・操作中のエラーなし。同じ確認用の部で、再生操作の前後の状態と録音は一致。確認ページは本物のセーブを使わない。

`check_member_record_stop.js`では実際の再生・停止関数と本物の録音データを使い、待機の停止、再生中の停止、自然終了、別の録音・本人への切り替え、古い待機の無効化を確認する。本番の終了処理を勝手に呼ばず、中止処理の中で次の音を始めても止めないことも確認する。

既存の現在の部員の試聴・最新の合奏の更新・停止後の表示・音源の再試行も実行済み。字形チェックは既存の不足記号5字のみ。
