# 指揮の入力タイミング

画面が重いと、一定の間隔で触れていても、処理が始まった時刻で「早い」「遅い」と判定され、テンポも揺れていた。入力イベントに残る時刻から処理待ちを差し引き、テンポ出し・二度押しの除外・拍の判定を実際に触れた時刻へそろえた。

`cdInputTime`は`Event.timeStamp`と`performance.now()`の差を音の時計から引く。時刻の値が無効なら音の時計を使い、古いブラウザの時刻の起点も扱う。250msを超えて遅れた入力では演奏を動かさない。複数指の2本目とマウスの右・中ボタンも除く。判定幅・指揮の効き・保存形式は維持。クリック音・振動・音量変更は、受け付けたときに処理する。

予告の数字は同じ文字で毎フレーム作り直さず、変わったときだけ更新する。図・画面の文言・音源を追加せず、オフラインで動く。

入力時刻の基準は[DOM StandardのEvent.timeStamp](https://dom.spec.whatwg.org/#dom-event-timestamp)。対象はJavaScriptの処理待ちによるズレ。スピーカーやイヤホンなど音声出力側の遅延は、[Web Audio仕様](https://www.w3.org/TR/webaudio/#dom-audiocontext-outputlatency)にある別の情報であり、今回の補正値に混ぜていない。実機での体感は未確認。

## 修正前後の再現

0.5秒おきの5タップに、100・80・160・50・120msの処理待ちを順に加えた。同じ`cdTap`・`BeatClock`で比較した。

| 結果 | 修正前 | 修正後 |
| --- | --- | --- |
| ぴったり | 0回 | 5回 |
| いい感じ | 2回 | 0回 |
| 早い・遅い | 3回 | 0回 |
| 5回目の拍の間隔 | 約0.516秒 | 0.500秒 |

修正前の実行は「5回ともぴったり」の回帰確認に失敗。`before.txt`がその結果。修正後の同じ確認は成功し、`after.txt`に記録した。

- Chromeの実際のクリックに60〜160msの負荷を掛けて8入力。処理待ちを差し引いた基準時刻との差は最大0.3ms。演奏中の4入力はすべてぴったりで、実際の41音源から`SampleVoice`で鳴る。数値はブラウザ内部の時計同士の比較で、実機の入出力全体の遅延を測ったものではない。
