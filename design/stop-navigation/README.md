# 止めた後も、次の操作へ戻る

## 見つかった不具合

合奏の停止ボタン、別タブの小さな再生バーの停止ボタンをEnterで押すと、そのボタンが消えて操作先がbodyへ落ちた。`before.json`に記録。次の操作へキーボードや読み上げで進む位置が分からなくなる。

## 変更

- 消える停止ボタンに操作先があったときだけ、その場所を覚える。合奏では「いまの音で合奏」、別タブでは現在のタブへ戻す。
- 手動停止・自然終了・読み込み中止に同じ処理を使う。フォーカスを戻す際にスクロールしない指定とし、タブも切り替えない。
- 終了の通知が次の音・待機を始めた場合や、結果画面・別の操作へフォーカスを移した場合はそのまま保つ。名前の入力中など、停止ボタン以外に操作先がある人には移動を行わない。
- 戻り先は既存の可視性の判定を使い、非表示・無効・モーダルの裏にある操作を選ばない。

再生・停止・終了通知の順序、音・採点・成長・セーブ形式・録音内容は変えていない。画面の文章・部品の配置・動く演出・素材・フォントの追加もない。

## 確認

- 実ブラウザの375×812のライト・ダークで、合奏を再生してEnterで停止すると「いまの音で合奏」へ戻る。再生と待機は終わり、部・録音は不変。
- 今週・部員・日誌の再生バーで停止すると、そのタブのボタンへ戻る。部員で812pxスクロールしてから止めても同じ位置。375×667でも667pxの位置を保った。
- 読み込み中止でも再生ボタンへ戻る。音源を解放しても古い待機は鳴らない。
- 短い区間の実際の録音を自然終了させ、合奏では再生ボタン、部員タブではタブのボタンへ戻る。合奏の405.5pxのスクロールも保つ。
- 録音が終わる前に現在の部員の名前の入力を始めた場合、入力欄と未保存の文字をそのまま保つ。
- `check_stop_navigation.js`で手動・自然終了・待機中止、部と演奏の保持、通知1回、次の音・待機・結果・別の操作の優先、非表示・無効・モーダルの裏への移動を防ぐこと、スクロールを変えない指定を確認。
- 最新の部への停止、個人録音、指揮結果の録音、選曲試聴、オーディション、録音カードの既存検証も合格。各`*-check.txt`に保存。
- 49操作で2027年度へ進行。33スクリプトの起動に成功し、コンソール警告・エラーなし。年度の進行と4タブの結果は`year-check.json`・`tabs-check.json`、各操作直後の観測は`browser-check.json`、照合結果は`browser-assertions.txt`に保存。
- 字の検査は既存の5記号（▶♩♮⤓𝄪）とコメントの「常」「了」「奪」を報告。画面の文字は変更していない。
