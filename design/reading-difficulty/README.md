# 曲の難しさを譜読みの時間にする

- 全15曲の `readDifficulty` を星1〜5で設定。`band.js` の `readingLoad` が必要な練習量を返し、`game.js` の譜読みの伸びだけをその値で割る。
- 練習量は星1から順に0.8・0.9・1・1.2・1.4。星3は従来と同じ。部員の実力・譜読みスキル・体力・やる気・指導力・区間ごとの覚えやすさは既存の式を使う。
- 個人練習は7割まで、そこから先は合奏という上限は保持。自由曲と課題曲はそれぞれの難しさが効き、既存の練習配分も保つ。
- 覚えた譜読みを減らさず、数値1つの古い譜読みと区間ごとの配列の両方を引きつぐ。保存形式やバージョンは変えない。
- 楽譜の音・音量・採点の倍率・基本能力の成長式は変更しない。全員が覚えた同じ演奏は、難しさの設定だけで採点が変わらないことを確認。
- 選曲・課題曲・定期演奏会と合奏に星を表示。押すと説明が出る。星は既存の自作SVGを使い、選曲の試聴もSVGにそろえた。星と3つの操作ボタンは44px以上。
- 曲のスクリプトに更新用のクエリを付け、確認ツールもそのURLを読めるようにした。素材やフォントのダウンロードなし。

## 確認

- `node tsukurikata/tools/check_reading_difficulty.js`：15曲の設定、1週間の進み方の順序、実力とスキル、個人練習の上限と合奏、2曲の配分、旧セーブ、覚えた値、採点の保持。
- 同じ曲と同じ部で難しさだけを変え、体力・やる気などの条件を固定した確認では、9割を覚えるまでの合奏が星1で5回、星3で6回、星5で8回。実際の各部の完成時期を予測する数字ではなく、時間差を確かめるための固定条件の試験。
- 375pxのライト・ダークで星と説明、15曲すべての文字切れと操作範囲、課題曲、定期演奏会の譜読みの保持、合奏の星表示を確認。
- 星5の「ウィリアム・テル」序曲で49回の画面更新を行い、新年度2027年へ進む。エラーなし、日誌も全文を保つ。4タブの両テーマでも横幅375pxに収まる。
- 顔、舞台、名前、入部、人選の既存チェックが成功。入部の旧セーブの確認は、以前に追加した元の名前の移行も照合する形に修正。
- JavaScriptの構文、`git diff --check` が成功。字のチェックは既存の不足記号5字のみ。
- iPhoneへのビルド・インストール・起動が成功。画面と処理の4ファイル、15曲のファイルが同梱内容と一致。実機の見た目はオーナーが確認する。

## 全15曲の成績比較

変更前はコミット `88f347a` のゲームを別の一時フォルダへ控えた。比較用に早送りツールへ `SIM_SEED` と `SIM_RUN` を追加し、同じ10組の入部条件を曲ごとに使った。指定がなければ従来どおり毎回違う部になる。

`SIM_SEED=20261026 bash tsukurikata/tools/sim_avg.sh` に15曲を渡して、変更前後でそれぞれ10回・3年を進めた。結果は `balance-before-a.txt`・`balance-before-b.txt`・`balance-after-a.txt`・`balance-after-b.txt` と `balance.json`。

初年度の県大会平均は全15曲で38.6〜44.0点となり、目安37〜47点の範囲内。2年目は64.4〜70.1点、3年目は73.0〜78.6点で、元の目安55〜67点・65〜75点を上回る曲も残る。変更前にも上回る曲があり、譜読みの時間差による成長や人選の違いも含めて記録した。採点倍率を変えて差を消す調整はしていない。

画面の確認は `screenshots/checks.json`、譜読みの確認は `mechanics-check.txt`。確認ページは本物のセーブや設定に書き込まない。
