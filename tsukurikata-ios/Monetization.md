# 無料＋本番後の広告／一度きりの購入で広告非表示

2026年11月2日。広告と買い切りについて相談中の案。オーナーの「480円」は検討額であり、方針の決定や実装の指示とは扱わない。決定として記録した前版を訂正した。実装は行っていない。既存のアーカイブは広告・課金なしの版であり、このモデルを含む配布版としては扱わない。

## 基本の形

- アプリのダウンロードは無料。
- 本番後の区切りで全面広告を表示する。
- 「広告を表示しない」を一度購入すると、以後の広告を非表示にする。自動更新や消耗品ではなく、非消耗型のアプリ内購入。
- 購入の復元も同じ場所へ用意する。
- 広告非表示は日本向け480円の一度きり購入を検討中。未決定で、App Store Connectへの価格登録も未実施。採用する場合、表示価格は実装で固定せず、App Storeから取得した表示価格を使う。他の国・地域の価格は未設定。
- 購入による能力や採点・出会いの有利不利は加えない。

## 広告を出す位置の案

今の`renderStageResult`で本番結果を見終え、次の活動へ移る区切りを候補とする。`data-act="next"`の直後に予告なく広告を重ねる仕様は確定しない。Googleの推奨ではContinue・Nextの前の区切りを勧めており、広告へ進むことが分かる操作と誤タップを避ける構成を検討する。

守りたい順序は、演奏 → 拍手・結果発表 → 結果を読む・聴き直す・保存する → 広告のための明確な区切り → 次の活動。広告より先に現在の進行を保存し、二度押しで二回進めない。表示位置の詳細は未決定。

次は広告を出さない。

- 演奏中・指揮中・拍手中・結果発表中。
- 合奏の試聴・お手本・成長の聴き比べ・録音の聴き直しを終えただけのとき。
- 課題曲から自由曲へ続く間。
- 相談、卒業のふり返り、保存・共有の操作。
- 初回案内の途中と最初の歓迎演奏。

私からの頻度の提案は、本番2回に1回まで、直近の表示から最低10分あける形から試すこと。これは未決定の本作品向け提案値で、広告サービスが一律に定める時間ではない。広告未準備・圏外・読み込み失敗なら待たせず進め、後から突然表示しない。Web版への導入は今回の検討範囲に含めない。

## iOSで作る際の要点

- 購入はStoreKitの非消耗型。検証済み取引・現在の購入権利と返金・失効の更新に従う。localStorageの自己申告だけで権利を決めない。
- 起動時は購入状態の確認を先に行い、広告非表示の利用者には広告の要求をしない。購入成功後は待機中の広告も出さない。
- 権利はゲームのセーブとは分ける。新しい部やセーブの読み込みで購入を失わせない。
- 購入画面は日誌へ小さくまとめる。機能の説明・App Storeの価格・一度きりの購入であること・購入の復元を表示する。商品未取得、購入の取り消し、承認待ち、復元失敗も区別する。
- 広告SDKはAdMobを候補にする。配信サービスの確定、アプリID・広告ユニットの登録、SDK導入、同意・年齢に応じた配信設定は未実施。実装中はテスト広告のみを使う。
- SDK・依存ファイルを導入する前に、リポジトリの規則に従い、ファイル名・入手元・容量を提示する。今回は何もダウンロードしていない。
- 広告の通信・SDKの取り扱うデータと課金を反映して、アプリ内と公開ページのポリシー・利用規約・ストア説明・プライバシー申告を更新する。現在の「広告・課金なし」「収集なし」の説明を広告対応版へそのまま流用しない。

## 先にそろえるもの

1. モデルと価格を相談して決める。480円は現時点の検討額。
2. 広告配信サービスとアプリID・広告ユニットの設定。
3. App Store Connectでの非消耗型商品の登録。
4. 実装・購入復元と広告表示の検証・ポリシー更新後の新しい配布版。
